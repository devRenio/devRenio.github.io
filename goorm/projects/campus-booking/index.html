문제와 맥락

동아리실·스터디룸 예약이 구글 시트와 카카오톡으로 분산되어 있어, 중복 예약과 확인 지연이 반복되었습니다. 특히 모집 시즌에는 예약 문의가 급증해 운영진의 수동 조율 비용이 컸습니다.

핵심 의사결정

Decision 1

Next.js App Router + Supabase로 MVP 구성

검토한 대안
Notion DB 연동, Google Calendar API 단독 사용
선택 이유
인증·DB·실시간 업데이트를 한 번에 해결하고 배포 파이프라인을 단순화할 수 있었습니다.
수용한 트레이드오프
Supabase 벤더 종속성을 감수했고, 커스텀 권한 모델은 2차 스프린트로 미뤘습니다.

Decision 2

예약 캘린더를 주 화면으로 배치

검토한 대안
리스트형 예약, 챗봇 기반 예약
선택 이유
사용자 인터뷰에서 '한눈에 빈 시간 확인'이 가장 자주 언급되었습니다.
수용한 트레이드오프
모바일 캘린더 UI 구현 난이도가 높아 일정 뷰는 1차에서 제외했습니다.

Decision 3

중복 예약 방지를 DB 트랜잭션으로 처리

검토한 대안
클라이언트 검증만 적용, 낙관적 UI
선택 이유
동시 예약 시나리오에서 데이터 정합성을 보장해야 했습니다.
수용한 트레이드오프
에러 메시지 UX를 단순화하는 대신 신뢰성을 우선했습니다.

결과

출시 8주 만에 214명이 사용했고, 운영진의 예약 조율 시간이 주당 3시간에서 30분 이하로 줄었습니다. 이후 다른 동아리로 확장 요청을 받아 2차 버전 기획으로 이어졌습니다.
